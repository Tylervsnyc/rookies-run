# Rookie's Revenge testing system — audit and rebuild, 2026-09-09

Tyler: "the rookie's revenge testing is a mess, I want to audit it so I can have more
reliable data and level building." This is what was found, what changed, and the rules
that now hold. Decisions Tyler made during the audit: pause the run-building routine;
**the ladder is the product**; fix the system (not just document it); Hard/Normal retry
budget deferred.

## What was wrong

**Broken pipes**
1. The nightly playtest job had timed out at 350 min on every fire since 2026-09-04
   (10 nights, all `cancelled`) after the sweep pool grew from 11 to 38 runs. Nobody
   knew: the Slack step was skipped when there was no output, so silence looked like
   success. A "TEMP, remove after tonight" cron from 2026-09-02 made it die twice a day.
2. A local midnight crontab ran dial/retry shards on the Mac; its last run died mid
   experiment (retries=5 never aggregated). The repo sourced chess-learning-tree's
   `.env.local` and Playwright, so it was not standalone.
3. The human funnel had produced six `[playtest]` lines ever, all art picks. Tyler's real
   verdicts ("too easy", "once you solve it you figured it out") landed in chat and memory
   files, never in the registry.

**Wrong things measured**
4. The bots graded a 10-rung ladder that was 1 approved + 9 `testing` runs, while players
   got a 13-run daily pool built before the combo gate existed. Every audit measured
   content players could not reach; every "live" grade was on content the ladder did not
   use.
5. Twelve `idea`-stage runs were compiled into the app bundle, never graded, never served.
6. `revenge-5` L10 was intentionally unwinnable, so the nightly printed IMPOSSIBLE every
   night and trained readers to ignore IMPOSSIBLE.

**Contradictory rules**
7. Five definitions of "good": a no-ability band in the README, a new-player 40-60% rule
   (the actual promotion gate), a `runDifficulty` score, a flat 60-80 pair band, and
   `docs/LADDER-SPEC.md`'s six checks known only to one script. The same run read TOO EASY
   in one report and PASS in another.
8. Retries were stated four ways (code 1, digest prose 3, test page 3, harness cap 5/99).
9. Spec constants and the signature-pair table were copy-pasted across three scripts; one
   keyed the wrong run. `ladder.ts` carried a pair table that went stale twice in two days.
10. 58 of 81 combo-library entries were accepted before the 80% ceiling and never
    re-screened; `SYNERGY.md` printed the floor-only rule; the ceiling was not recorded.

**Untrustworthy numbers**
11. No number knew its engine. Rules changed on six days in a week (refills, seeding, the
    capturing king, king-once-per-phase and its revert, summoning sickness, Aegis,
    Sacrifice). The capturing king broke six of ten rungs — one to 0% — and was found a day
    later by hand.
12. Noise exceeded the window: 16 trials/cell is ±17-22 points; the spec window is ±8; the
    gate is ≤8%. No report printed an interval. "182 cells moved more than 15 points in one
    night" was mostly noise.
13. Bot blind spots leaked into verdicts: 0% cast rate cards sat in tier tables; the MCTS
    bot was exported under the `T5` id.
14. No artifact schema; three ladder files measured the same rungs under three rule-sets in
    one flat directory; `latest.md` copies went 62 days stale; the nightly deleted raw output.

**Sprawl**
15. 66 harness files, 25 one-offs, a dead rank-8 pipeline still on `npm run playtest`, a
    diverged copy of it in chess-learning-tree that a session ran by hand on 2026-09-06
    (committing a digest whose headline was that pipeline's bug). ~130 result files
    untracked, including the contract and its auditor.
16. 25 runs in testing, 12 in idea, a 3-hour routine adding more.

## The standing rules

1. **One contract.** `scripts/run-playtest/spec.ts` = `docs/LADDER-SPEC.md`. Change both or neither.
2. **Error bars or no verdict.** INCONCLUSIVE is an answer; "probably fine" is not.
3. **No number without an engine fingerprint.** `npm run playtest:ladder -- --check-stale` before quoting a rung. Read the engine-regression Slack line after any `lib/run` push.
4. **Results go through `results.ts`.** No dated JSON in the data root, no per-experiment shapes.
5. **The ladder is the product.** `LADDER_RUNG_IDS` == live == `REVENGE_RUN_IDS`; the build asserts it.
6. **Testing ≤ 5 runs.** A queue you can play, not a parking lot.
7. **No local crons.** GitHub Actions or an explicit command. A dead night posts NIGHTLY FAILED.
8. **Verdicts are one command.** `npx tsx scripts/pipeline.ts verdict <id> SHIP|TUNE|KILL|BUG "<note>"`.

## Open, deliberately

- **Hard vs Normal** both give 1 retry and differ only in king behavior (Tyler: decide later).
- **`lib/run/endless.ts` imports `finale-remeasure-2026-09-06.json`** (pre capturing king) to decide which levels are pair-gated. It works, but it is a stale measurement baked into app logic. Replace with a `pairGated` flag on the level or a read of the latest filed audit.
- **The first ladder audit at full budget has not run yet.** The nightly will file one at 48 trials/cell tonight; run `npm run playtest:ladder` locally (~96 trials, ~1h on 8 cores) for numbers of record. The quick smoke already read rung 1 (The Slash) as TOO HARD, consistent with the 2026-09-08 finding (37.8%).
- **The combo-run routine is paused.** Before re-enabling, its prompt must learn: N = 1 + highest id across `lib/run/runs/` AND `_ideas/`; a new run goes to `testing` only if the cap allows, else `idea` in `_ideas/`; grade with `ladder-audit`-style checks from `spec.ts`.
- **58 pre-ceiling combo-library entries** still need `combo-discover.ts --rescreen` (not built).
- **Nightly auto-demotion of BROKEN candidates** was planned and not built; candidates are not swept nightly now, so it has nothing to act on until a candidate sweep returns.
- **engine-regression uses `cancel-in-progress`**: on a busy push day only the last push gets graded. Fine for a gate; remember it when reading Slack.
- The plan's per-area subdirectories (`core/`, `nightly/`, …) were not created: 52 live files import each other flatly and the move would have been churn without safety. The README's file table is the map.
- Remaining `.claude/agents/*` in this repo (hypothesis-loop, mutator-explorer, regression-watcher, …) date from the rank-8 pipeline and were not reviewed.
